## 使用说明

这套资料用于把“三天学习路线”真正落到源码、口述和验收上。学习时始终使用三种标签：

- `当前源码`：能在仓库现有 Java、Lua 或 YAML 文件中直接验证。
- `教程设计`：六份编号教程中的演进说明，可能与最终源码不同。
- `生产改进`：为了可靠性、可用性或面试表达提出的增强方案，不能说成项目已经实现。

建议每天新建一份自己的答题纸，只写调用链、状态、问题和口述关键词，不抄整段教程。

## 当前环境结论

2026-07-29 在仓库根目录核对：

```text
java -version：JDK 21
mvn -version：Maven 实际使用 JDK 8
项目 pom.xml：source/target 为 Java 17
常见 JDK 安装目录：只发现 JDK 21 和 JDK 8，未发现 JDK 17
```

因此当前不能据此声称项目编译通过。先在 IDE 或 Maven 启动脚本中把 Maven JDK 切到 17，再执行：

```powershell
cd "后端代码\qiyu-live-app"
mvn -DskipTests package
```

JDK 21 虽可能编译 Java 17 源码，但本项目的既定基线是 JDK 17；冲刺阶段优先保持构建和运行环境一致。

## 四种通信方式先分清

| 通信方式 | 本项目用途 | 典型特征 |
| --- | --- | --- |
| HTTP | 浏览器访问 Gateway/API | 请求响应、面向前端、短连接语义 |
| Dubbo RPC | API、Gateway、provider 之间同步调用 | 强类型接口、同步得到结果、受超时和重试影响 |
| Kafka | IM、送礼、在线状态、库存回滚等异步解耦 | 削峰、异步、可能重复，必须设计幂等 |
| WebSocket | 浏览器与 IM Core 保持双向长连接 | 服务端主动推送、需要心跳、连接路由和重连 |

## 三天执行规则

- 每读完一个入口类，闭眼写一次“下一跳是谁”，写不出才回源码。
- 每条链路至少记录 3 个“当前源码问题”，并给出触发条件和影响。
- 每个生产改进必须回答：解决什么故障、状态放在哪里、如何幂等。
- 每天至少录音两次。第一次照稿，第二次只看关键词，单段控制在 2 分钟。
- 不把“用了 Redis/Kafka”直接等同于高并发，也不把 `setIfAbsent` 直接称为完整分布式锁。
- 不把源码中的注释、`TODO`、本地线程池和本地 `DelayQueue` 包装成生产级能力。
