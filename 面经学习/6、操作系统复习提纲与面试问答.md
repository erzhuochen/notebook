# 一、体系复习提纲

## 1. 学习目标

能从 Java 后端服务运行过程出发，讲清进程线程、用户态内核态、上下文切换、内存、进程通信、IO 多路复用和性能排查。

## 2. 核心主线

```text
Spring Boot 应用启动
-> 形成一个 JVM 进程
-> 请求由线程处理
-> 线程访问 CPU、内存、网络、磁盘
-> 涉及系统资源时通过系统调用进入内核态
-> 高并发下重点关注线程数、阻塞、上下文切换、IO 模型
```

## 3. 必会知识点

### 进程和线程

- 进程是资源分配的基本单位。
- 线程是 CPU 调度的基本单位。
- 同一进程内线程共享堆、方法区、文件描述符等资源。
- 每个线程拥有独立的栈、程序计数器、寄存器上下文。

### 用户态和内核态

- 用户态运行普通应用代码，权限较低。
- 内核态运行操作系统内核代码，权限较高。
- 系统调用会导致用户态和内核态切换。

### 上下文切换

- CPU 从一个执行流切换到另一个执行流时，需要保存和恢复现场。
- 线程切换通常比进程切换轻，但过多线程仍会造成调度成本。
- 锁竞争、阻塞 IO、线程数过多都会增加上下文切换。

### 内存管理

- 虚拟内存让每个进程看到独立地址空间。
- 页表负责虚拟地址到物理地址的映射。
- 缺页中断会触发磁盘读取或页面调入。
- Java 堆、栈、直接内存最终都依赖操作系统内存。

### IO 模型

- 阻塞 IO：线程等待 IO 完成。
- 非阻塞 IO：立即返回，需要不断检查。
- IO 多路复用：一个线程监听多个连接。
- 异步 IO：内核完成后通知应用。

### select / poll / epoll

- select：位图，有数量限制，每次全量复制和遍历。
- poll：数组，无固定数量限制，但仍全量遍历。
- epoll：事件驱动，就绪队列，更适合高并发连接。

## 4. 易错点

- 系统调用不等于进程切换。
- 线程多不一定吞吐高，过多线程会带来上下文切换和内存成本。
- epoll 适合大量连接、少量活跃的网络场景，不是所有场景都必然最优。
- 协程/虚拟线程减少的是线程创建和切换成本，不是让 CPU 变多。
