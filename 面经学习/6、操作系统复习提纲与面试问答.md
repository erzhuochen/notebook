## 二、高频面试题

### 1. 进程和线程有什么区别？

回答：

进程和线程可以先从两个关键词理解：**进程是资源分配的基本单位，线程是 CPU 调度的基本单位**。

**进程**可以理解成一个正在运行的程序实例。操作系统会给每个进程分配相对独立的资源，比如虚拟地址空间、文件描述符、堆、代码段、数据段等。不同进程之间默认是隔离的，一个进程不能随便访问另一个进程的内存。

**线程**是进程内部的执行单元。一个进程里可以有多个线程，这些线程共享同一个进程的大部分资源，比如堆、方法区、打开的文件、网络连接等；但每个线程也有自己独立的执行现场，比如线程栈、程序计数器、寄存器上下文。

举个例子：浏览器是一个程序，它可以有多个进程，比如页面进程、插件进程、GPU 进程。某个页面进程里又可能有多个线程，比如渲染线程、JS 执行线程、网络线程。进程之间隔离更强，线程之间共享更多资源。

两者的主要区别：

1. **资源归属不同**：进程拥有独立地址空间和资源；线程共享所属进程的资源。
2. **调度粒度不同**：线程是 CPU 调度的基本单位；进程更多体现为资源容器。
3. **通信方式不同**：进程间通信通常需要 IPC，比如管道、消息队列、共享内存、信号、Socket；同一进程内线程可以直接读写共享变量，但必须处理同步问题。
4. **创建和切换成本不同**：进程创建和切换通常更重，因为涉及更多资源和地址空间；线程更轻，因为共享进程资源，只需要维护线程自己的栈和执行上下文。
5. **隔离性不同**：进程隔离性更好，一个进程崩溃通常不会直接破坏另一个进程；线程共享同一进程资源，一个线程写坏共享内存可能影响同进程的其他线程。

#### 追问 1：为什么线程切换通常比进程切换轻？

回答：

线程切换通常比进程切换轻，核心原因是：**同一进程内的线程共享地址空间，切换线程时通常不需要切换页表；进程切换通常要切换地址空间**。

进程切换时，操作系统要保存当前进程的上下文，再恢复另一个进程的上下文。除了寄存器、程序计数器、栈指针等执行现场，还可能需要切换页表。页表一换，CPU 之前缓存的虚拟地址到物理地址映射，也就是 **TLB**，可能大量失效。TLB 失效后，后续内存访问要重新查页表，成本更高。

线程切换时，如果两个线程属于同一个进程，它们共享同一套地址空间和页表，所以通常不需要切换页表，TLB 的影响更小。线程切换主要保存和恢复线程自己的寄存器、程序计数器、栈指针等。

但要注意，不能绝对说“线程切换时缓存和 TLB 一定不会失效”。线程切换仍然可能影响 CPU cache，因为不同线程访问的数据不同，会造成缓存命中率下降；只是相比进程切换，它通常少了地址空间切换这类重成本。

可以类比成：进程切换像换到另一家公司办公，要换工位、门禁、资料柜；线程切换像同一家公司不同员工轮流用同一间办公室，仍要换人和桌面资料，但不用换整套办公环境。

#### 追问 2：Java 中线程共享哪些数据，不共享哪些数据？

回答：

在 Java 中，同一个 JVM 进程里的多个线程共享**堆**和**方法区/元空间中的类元数据**，每个线程独享自己的**程序计数器、本地方法栈、Java 虚拟机栈**。

共享的部分：

1. **堆**：对象实例基本都在堆上，多个线程可以同时访问同一个对象。所以成员变量、集合对象、缓存对象如果被多个线程共享，就需要考虑线程安全。
2. **方法区/元空间相关数据**：类信息、运行时常量池、静态变量等是线程共享的。
3. **进程级资源**：比如打开的文件、Socket 连接等也可能被多个线程共享使用。

线程私有的部分：

1. **程序计数器**：记录当前线程执行到哪条字节码指令。
2. **Java 虚拟机栈**：每个方法调用会创建栈帧，局部变量表、操作数栈等在线程自己的栈里。
3. **本地方法栈**：服务 native 方法调用。

例子：方法里的局部变量 `int x = 1` 通常在线程自己的栈帧里，不会被其他线程直接访问；但如果局部变量引用了一个堆上的对象，比如 `User user = sharedUser`，那么 `user` 这个引用变量本身在线程栈里，但它指向的对象在堆上，其他线程也可能访问到这个对象。

#### 追问 3：一个线程崩溃会不会影响整个进程？

回答：

要分情况看。普通情况下，一个 Java 线程因为未捕获异常而结束，通常只会终止这个线程本身，不会直接让整个 JVM 进程退出。但如果这个线程破坏了共享状态，或者抛出的是严重错误，就可能间接影响整个进程。

比如一个普通工作线程执行任务时抛出 `RuntimeException`，没有捕获，这个线程会结束。线程池里的工作线程还可能被线程池补充一个新线程，整个进程不一定退出。

但下面几种情况可能影响整个进程：

1. **主线程退出且没有其他非守护线程**：JVM 可能结束。
2. **线程破坏共享数据**：比如一个线程更新共享 Map 时写了一半异常退出，其他线程读到不一致状态，业务可能整体出错。
3. **严重错误**：比如 `OutOfMemoryError`、`StackOverflowError`、JVM 崩溃、native 代码段错误，可能影响整个 JVM 进程。
4. **关键线程死亡**：比如负责接收请求、心跳、调度任务的核心线程异常退出且没有恢复机制，服务可能变得不可用。

所以更准确的说法是：**线程异常通常不会像进程隔离那样被完全隔离；一个线程普通异常可能只影响自己，但由于线程共享进程资源，严重错误或共享状态破坏可能影响整个进程**。
