## 二、高频面试题

### 1. 进程和线程有什么区别？

简答版：
进程是资源分配的基本单位，线程是 CPU 调度的基本单位。进程之间地址空间隔离，线程共享同一进程的堆、方法区等资源，但每个线程有自己的栈、程序计数器和寄存器上下文。

展开版：
进程拥有独立的虚拟地址空间、文件描述符表等资源，进程切换时可能涉及页表切换和 TLB 刷新，成本较高。线程属于进程内部的执行单元，同一进程内的线程共享大部分资源，所以创建和切换成本更低，但共享内存也意味着需要处理线程安全问题。

常见追问：
- 为什么线程切换比进程切换轻？
- 一个线程崩溃会不会影响整个进程？
- Java 中线程共享哪些数据，不共享哪些数据？

### 2. 用户态和内核态是什么？

简答版：
用户态是普通程序运行的低权限状态，内核态是操作系统内核运行的高权限状态。用户程序需要通过系统调用进入内核态，请求操作系统完成 I/O、内存、进程调度等操作。

展开版：
CPU 通过权限级别隔离用户程序和内核。普通应用不能直接访问硬件或执行特权指令，否则系统会不安全。比如读文件、网络收包、创建线程，都需要通过系统调用让内核完成。切换到内核态本身不是绝对不能接受，真正需要关注的是高频、额外、可避免的切换。

常见追问：
- 系统调用和普通函数调用有什么区别？
- 为什么阻塞 I/O 可能导致线程上下文切换？
- synchronized 膨胀为重量级锁为什么成本更高？

### 3. 什么是上下文切换？

简答版：
上下文切换是 CPU 从一个执行单元切换到另一个执行单元时，保存当前运行状态并恢复另一个运行状态的过程。

展开版：
上下文包括程序计数器、寄存器、栈指针等信息。线程切换通常不需要切换地址空间；进程切换除了保存和恢复寄存器，还可能切换页表，导致 TLB 和缓存命中率下降，因此成本更高。

常见追问：
- 上下文切换为什么会影响性能？
- 系统调用一定会导致进程切换吗？
- 如何减少频繁上下文切换？

### 4. 系统调用和进程切换有什么区别？

简答版：
系统调用只是从用户态切到内核态，仍可能在当前进程上下文中执行；进程切换是 CPU 从一个进程切换到另一个进程，成本更高。

展开版：
系统调用发生时，当前进程请求内核服务，比如 read、write、socket。此时 CPU 权限级别变化，但不一定更换当前进程。进程切换则需要保存当前进程上下文，调度另一个进程，切换地址空间和页表，开销明显更大。

常见追问：
- read 调用在数据未准备好时会发生什么？
- 为什么进程切换可能导致缓存失效？
- 线程阻塞和 CPU 调度有什么关系？

### 5. 协程和线程有什么区别？

简答版：
线程由操作系统调度，协程通常由用户态运行时调度。协程更轻量，切换成本更低，但需要运行时支持。

展开版：
传统线程的创建、阻塞、唤醒、调度都需要操作系统参与。协程把调度放到用户态，切换时不需要频繁陷入内核，因此可以支持更高并发。Java 虚拟线程可以理解为 JVM 管理的轻量线程，适合大量 I/O 阻塞任务。

常见追问：
- 协程适合 CPU 密集型任务吗？
- Java 虚拟线程和平台线程是什么关系？
- 协程阻塞时会不会阻塞底层线程？

### 6. 进程间通信有哪些方式？

简答版：
常见 IPC 有管道、消息队列、共享内存、信号、信号量、Socket。共享内存最快，但需要额外同步；Socket 可以跨机器通信。

展开版：
管道适合简单的父子进程通信；消息队列适合结构化消息传递；共享内存避免频繁拷贝，性能最高，但要自己处理并发同步；信号用于异步通知；信号量主要用于同步和互斥；Socket 抽象出网络通信端点，是最通用的通信方式。

常见追问：
- 共享内存为什么最快？
- 信号和信号量有什么区别？
- Socket 为什么既能本机通信也能跨机器通信？

### 7. 虚拟内存解决了什么问题？

简答版：
虚拟内存为每个进程提供独立、连续的地址空间，同时通过页表映射到真实物理内存，实现隔离、保护和内存扩展。

展开版：
程序看到的是虚拟地址，不直接操作物理地址。操作系统通过页表把虚拟页映射到物理页。这样不同进程可以使用相同的虚拟地址而互不影响，也可以把暂时不用的页面换出到磁盘，提升内存利用率。

常见追问：
- 缺页异常是什么？
- 页表太大怎么办？
- TLB 的作用是什么？

### 8. Page Cache 是什么？

简答版：
Page Cache 是操作系统用内存缓存磁盘文件数据的机制，用来减少真实磁盘 I/O。

展开版：
读文件时，内核会先检查 Page Cache。如果命中，直接从内存返回；如果未命中，再从磁盘加载到 Page Cache。写文件时，数据通常先写入 Page Cache，再由内核异步刷盘。它提升了文件 I/O 性能，但也意味着应用写成功不一定代表数据已经落盘。

常见追问：
- Page Cache 和 Buffer Cache 有什么区别？
- 为什么顺序读写比随机读写快？
- mmap 和 Page Cache 有什么关系？

### 9. 阻塞 I/O、非阻塞 I/O、I/O 多路复用有什么区别？

简答版：
阻塞 I/O 会让线程等待数据准备；非阻塞 I/O 如果数据没准备好会立即返回；I/O 多路复用允许一个线程同时监听多个连接的 I/O 事件。

展开版：
阻塞 I/O 编程简单，但高并发下线程数量容易膨胀。非阻塞 I/O 需要不断轮询，可能浪费 CPU。I/O 多路复用把“等待多个连接是否就绪”交给内核，比如 select、poll、epoll，线程只处理已经就绪的连接。

常见追问：
- Reactor 模型和 I/O 多路复用有什么关系？
- 非阻塞 I/O 是否等于异步 I/O？
- Java NIO 用到了什么思想？

### 10. select、poll、epoll 有什么区别？

简答版：
select 使用固定大小 bitmap，poll 使用数组，二者都需要线性扫描；epoll 使用事件驱动机制，适合大量连接中只有少量活跃的场景。

展开版：
select 有 fd 数量限制，每次调用都要把 fd 集合从用户态拷到内核态，并线性遍历。poll 去掉了固定大小限制，但仍然要线性扫描。epoll 把关注的 fd 注册到内核，事件就绪后放入就绪队列，应用只需要取就绪事件，减少重复拷贝和无效遍历。

常见追问：
- epoll 一定比 select 快吗？
- epoll 的 LT 和 ET 有什么区别？
- 惊群问题是什么？

## 三、易错点

- 用户态切内核态不等于进程切换，二者成本不同。
- 线程共享进程资源，但线程栈、程序计数器、寄存器上下文是独立的。
- 共享内存快，但不是天然安全，必须配合同步机制。
- 非阻塞 I/O 不等于异步 I/O；非阻塞强调调用立即返回，异步强调内核完成后通知。
- epoll 适合高并发连接，但如果连接数很少或全部都很活跃，优势不一定明显。
