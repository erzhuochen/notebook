# 8、JVM 系统学习笔记

## 一、学习目标

学完 JVM 后，要能讲清楚三件事：

1. Java 程序是如何被加载和执行的。
2. Java 对象在内存中如何存放，垃圾回收如何判断和回收对象。
3. 出现内存问题或 GC 问题时，如何定位方向。

## 四、高频面试题

### 1. JVM 运行时数据区有哪些？

简答版：
主要包括程序计数器、Java 虚拟机栈、本地方法栈、Java 堆、方法区。堆和方法区是线程共享的，程序计数器、虚拟机栈、本地方法栈是线程私有的。

展开版：
程序计数器记录当前线程执行到哪条字节码指令；虚拟机栈保存方法调用时的栈帧；本地方法栈服务 native 方法；堆存放对象实例，是 GC 重点管理区域；方法区存放类元信息、常量、静态变量等。

常见追问：
- 哪些区域会发生 OOM？
- 栈溢出和堆溢出有什么区别？
- JDK 8 之后方法区有什么变化？

### 2. 类加载过程是什么？

简答版：
类加载过程包括加载、验证、准备、解析、初始化五个阶段。

展开版：
加载阶段把 class 字节流读入 JVM，并生成 Class 对象。验证阶段确保字节码安全合法。准备阶段为类变量分配内存并设置零值。解析阶段把符号引用转成直接引用。初始化阶段执行类构造器 clinit，完成静态变量赋值和静态代码块执行。

常见追问：
- 准备阶段和初始化阶段有什么区别？
- 类什么时候会初始化？
- clinit 和 init 有什么区别？

### 3. 什么是双亲委派模型？

简答版：
类加载器收到加载请求时，先委派给父加载器加载，父加载器加载不了时，子加载器才尝试加载。

展开版：
双亲委派可以保证 Java 核心类库的安全和唯一性。比如用户自己写一个 java.lang.String，正常情况下不会替代 JDK 自带的 String，因为请求会先交给 Bootstrap ClassLoader。

常见追问：
- 双亲委派解决了什么问题？
- 什么场景会打破双亲委派？
- Tomcat 为什么需要自己的类加载机制？

### 4. Java 对象在内存中由哪些部分组成？

简答版：
对象通常由对象头、实例数据和对齐填充组成。数组对象还会包含数组长度。

展开版：
对象头包括 Mark Word 和类型指针。Mark Word 存储哈希码、GC 年龄、锁状态等信息；类型指针指向类元数据；实例数据是对象真正的字段内容；对齐填充是为了满足内存对齐要求。

常见追问：
- Mark Word 和 synchronized 有什么关系？
- 指针压缩是什么？
- 一个 Object 对象大概占多少字节？

### 5. 如何判断对象可以被回收？

简答版：
JVM 主要使用可达性分析。从 GC Roots 出发，无法被访问到的对象就可以被回收。

展开版：
GC Roots 包括虚拟机栈中引用的对象、方法区中类静态属性引用的对象、常量引用的对象、JNI 引用的对象等。可达性分析比引用计数更能解决循环引用问题。

常见追问：
- 引用计数法有什么问题？
- 哪些对象可以作为 GC Roots？
- finalize 能让对象复活吗？

### 6. Java 有哪些引用类型？

简答版：
Java 有强引用、软引用、弱引用、虚引用。

展开版：
强引用只要还存在就不会被回收。软引用在内存不足时可能被回收，常用于缓存。弱引用只要发生 GC 就可能被回收，ThreadLocalMap 的 key 就是弱引用。虚引用不能直接获取对象，主要用于跟踪对象回收。

常见追问：
- ThreadLocal 为什么用弱引用？
- 软引用适合做什么？
- 虚引用有什么用？

### 7. 常见垃圾回收算法有哪些？

简答版：
常见算法有标记-清除、标记-复制、标记-整理。

展开版：
标记-清除先标记可回收对象再清理，容易产生内存碎片。标记-复制把存活对象复制到另一块内存，适合存活率低的新生代。标记-整理把存活对象向一端移动，清理边界外内存，适合老年代。

常见追问：
- 新生代为什么适合复制算法？
- 老年代为什么通常不用复制算法？
- 内存碎片会带来什么问题？

### 8. G1 垃圾收集器有什么特点？

简答版：
G1 把堆划分成多个 Region，以可预测停顿为目标，优先回收收益高的 Region。

展开版：
G1 不再严格按连续的新生代和老年代划分物理内存，而是把堆拆成多个 Region。它可以根据每个 Region 的垃圾比例和回收成本，选择回收价值最高的一批 Region，因此叫 Garbage First。

常见追问：
- G1 为什么适合大堆？
- 什么是 Remembered Set？
- G1 和 CMS 有什么区别？

### 9. 常见 OOM 有哪些？

简答版：
常见有 Java heap space、Metaspace、StackOverflowError、Direct buffer memory。

展开版：
堆溢出通常是对象过多或内存泄漏；元空间溢出通常和类加载过多有关；栈溢出通常是递归太深或栈帧过大；直接内存溢出常见于 NIO 或堆外内存使用不当。

常见追问：
- 内存泄漏和内存溢出有什么区别？
- 如何排查堆 OOM？
- 为什么直接内存不在堆里也会 OOM？

### 10. JVM 调优一般怎么做？

简答版：
先明确现象，再收集数据，分析 GC 日志和内存快照，定位是内存不足、对象创建过快、内存泄漏还是参数不合理，最后小步调整并验证。

展开版：
调优不能一上来就改参数。要先看 CPU、内存、GC 次数、GC 耗时、吞吐量、停顿时间等指标。常用信息包括 GC 日志、堆转储文件、线程栈。参数调整要围绕目标进行，比如降低停顿、提高吞吐、减少 Full GC。

常见追问：
- Minor GC、Major GC、Full GC 有什么区别？
- 什么情况下会频繁 Full GC？
- 如何判断是内存泄漏还是内存确实不够？

## 五、易错点

- 栈里存的是栈帧，不是对象本体；对象通常在堆上。
- 方法区是规范概念，JDK 8 常见实现是元空间。
- 引用计数法无法很好处理循环引用，JVM 主流使用可达性分析。
- Young GC 不等于 Full GC，停顿范围和触发原因不同。
- 调优不是背参数，而是先定位现象和瓶颈。
