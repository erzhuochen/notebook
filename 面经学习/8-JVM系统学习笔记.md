# 一、JVM 运行时数据区

## 核心主线

```text
Java 源码
-> 编译成 .class 字节码
-> 类加载器加载到 JVM
-> 运行时使用内存区域保存对象、栈帧、类信息等
-> GC 主要管理堆内存
```

## 关键区域

### 程序计数器

- 线程私有。
- 记录当前线程正在执行的字节码指令地址。
- 线程切换后依靠它恢复执行位置。
- 是 JVM 规范中唯一没有规定 OOM 的区域。

### Java 虚拟机栈

- 线程私有。
- 每次方法调用都会创建一个栈帧。
- 栈帧中包含局部变量表、操作数栈、动态链接、方法返回地址。
- 常见异常：StackOverflowError、OutOfMemoryError。

### 本地方法栈

- 线程私有。
- 为 Native 方法服务。

### 堆

- 线程共享。
- 主要存放对象实例和数组。
- 是 GC 管理的主要区域。
- 常见异常：OutOfMemoryError: Java heap space。

### 方法区 / 元空间

- 线程共享。
- 存放类元信息、常量、静态变量、即时编译后的代码等。
- JDK 8 后方法区实现从永久代变为元空间，元空间使用本地内存。

## 易错点

- 方法区是 JVM 规范概念，永久代/元空间是 HotSpot 的实现。
- 栈管方法调用，堆管对象实例。
- 局部变量如果是对象引用，引用本身在栈帧中，对象实例在堆中。

# 二、对象创建与内存布局

## 对象创建流程

```text
遇到 new 指令
-> 类加载检查
-> 分配内存
-> 初始化零值
-> 设置对象头
-> 执行 <init> 构造方法
```

## 内存分配方式

- 指针碰撞：堆内存规整时，移动指针即可分配。
- 空闲列表：堆内存不规整时，维护可用内存列表。

## 并发分配安全

- CAS + 失败重试。
- TLAB：每个线程在堆中预先分配一小块私有区域，减少竞争。

## 对象内存布局

```text
对象头
实例数据
对齐填充
```

### 对象头

- Mark Word：存储哈希码、GC 年龄、锁状态等。
- Klass Pointer：指向类元数据。
- Array Length：数组对象额外保存数组长度。

## 易错点

- new 指令执行后，不代表构造方法已经完成。
- 对象头中的 Mark Word 会随着锁状态变化。
- 对象大小通常需要按 8 字节对齐。

# 三、类加载机制

## 类加载阶段

```text
加载
-> 验证
-> 准备
-> 解析
-> 初始化
```

### 加载

- 通过类的全限定名获取二进制字节流。
- 转换为方法区中的运行时数据结构。
- 在堆中生成 Class 对象作为访问入口。

### 验证

- 确保字节码合法、安全，不会破坏 JVM。

### 准备

- 为类变量分配内存并设置默认初始值。
- 注意：这里不是代码中写的显式赋值。

### 解析

- 把常量池中的符号引用替换为直接引用。

### 初始化

- 执行类构造器 `<clinit>()`。
- 对静态变量赋值，执行 static 代码块。

## 双亲委派模型

类加载器收到加载请求时，先委派父加载器加载，父加载器无法加载时，子加载器才尝试加载。

优点：

- 避免类重复加载。
- 保护 Java 核心类库安全，例如防止自定义 `java.lang.String` 被加载。

## 易错点

- 准备阶段给静态变量赋默认值，初始化阶段才执行显式赋值。
- 双亲委派不是强制规范，是一种推荐模型和常见实现。

# 四、垃圾回收基础

## 如何判断对象可回收

### 引用计数法

- 给对象维护引用计数。
- 缺点：无法解决循环引用。

### 可达性分析

- 从 GC Roots 出发，能到达的对象是存活对象，到达不了的对象可回收。

常见 GC Roots：

- 虚拟机栈中引用的对象。
- 方法区中类静态属性引用的对象。
- 方法区中常量引用的对象。
- 本地方法栈中 JNI 引用的对象。
- 活跃线程对象、锁持有对象等。

## 引用类型

- 强引用：只要存在就不会被 GC。
- 软引用：内存不足时可能回收，适合缓存。
- 弱引用：下一次 GC 就可能回收。
- 虚引用：不能通过它获取对象，主要用于跟踪对象回收。

## 垃圾回收算法

### 标记-清除

- 标记可回收对象，再清除。
- 缺点：产生内存碎片。

### 标记-复制

- 把存活对象复制到另一块区域。
- 优点：简单高效，无碎片。
- 缺点：浪费一部分空间。

### 标记-整理

- 标记后把存活对象向一端移动。
- 优点：减少碎片。
- 缺点：移动对象成本较高。

### 分代收集

- 新生代对象朝生夕死，适合复制算法。
- 老年代对象存活时间长，适合标记清除或标记整理。

# 五、常见垃圾收集器

## Serial

- 单线程收集器。
- 简单，但会 Stop The World。

## ParNew

- Serial 的多线程版本。

## Parallel Scavenge

- 注重吞吐量。
- 适合后台计算任务。

## CMS

- 目标是降低停顿时间。
- 基于标记清除，可能产生碎片。

## G1

- 面向服务端应用。
- 把堆划分为多个 Region。
- 可以按收益优先回收垃圾最多的 Region。
- 目标是在可控停顿时间内获得较高回收效率。

## ZGC / Shenandoah

- 面向低延迟。
- 校招了解即可。

# 六、OOM 与排查

## 常见 OOM

- Java heap space：堆内存不足。
- GC overhead limit exceeded：GC 频繁但回收效果差。
- Metaspace：类元信息过多。
- Direct buffer memory：直接内存不足。
- Unable to create new native thread：无法创建更多本地线程。

## 排查思路

```text
确认 OOM 类型
-> 保留现场和日志
-> 查看 JVM 参数
-> 获取堆转储文件
-> 分析大对象、对象数量、引用链
-> 判断是内存泄漏还是内存配置不足
-> 修复代码或调整参数
```

常用工具：

- jps：查看 Java 进程。
- jstack：查看线程栈。
- jmap：查看堆信息、导出 dump。
- jstat：查看 GC 情况。
- MAT / VisualVM：分析 dump。

# 面试问答附录

## Q1：JVM 运行时数据区有哪些？

标准回答：

> JVM 运行时数据区主要包括程序计数器、虚拟机栈、本地方法栈、堆、方法区。程序计数器、虚拟机栈、本地方法栈是线程私有的；堆和方法区是线程共享的。堆主要存放对象实例，是 GC 管理的主要区域；栈主要保存方法调用过程中的栈帧。

## Q2：对象创建过程是什么？

标准回答：

> JVM 遇到 new 指令后，会先检查类是否已经加载，然后为对象分配内存，初始化零值，设置对象头，最后执行构造方法。内存分配可能使用指针碰撞或空闲列表，并发场景下可以通过 CAS 或 TLAB 保证分配安全。

## Q3：类加载过程是什么？

标准回答：

> 类加载过程包括加载、验证、准备、解析、初始化。加载是读取字节码并生成 Class 对象；验证是保证字节码安全；准备是给类变量分配内存并设置默认值；解析是把符号引用转成直接引用；初始化是执行静态变量赋值和 static 代码块。

## Q4：什么是双亲委派？

标准回答：

> 双亲委派是指类加载器收到类加载请求后，先交给父加载器加载，父加载器加载不了时，子加载器才自己加载。这样可以避免类重复加载，也可以保护 Java 核心类库不被随意替换。

## Q5：GC 怎么判断对象是否可回收？

标准回答：

> 主流 JVM 使用可达性分析，从 GC Roots 出发向下搜索，能被访问到的对象是存活对象，访问不到的对象可以被回收。常见 GC Roots 包括栈中引用的对象、静态变量引用的对象、常量引用的对象、本地方法引用的对象等。

## Q6：Minor GC、Major GC、Full GC 有什么区别？

标准回答：

> Minor GC 通常发生在新生代；Major GC 通常指老年代 GC，但不同语境可能有差异；Full GC 通常会回收整个堆和方法区相关资源，停顿时间更长。面试中回答时可以先说明术语在不同收集器中可能不完全一致，再讲它们的大致范围。

## Q7：发生 OOM 怎么排查？

标准回答：

> 先看 OOM 类型和 GC 日志，确认是堆、元空间、直接内存还是线程数问题。然后保留 dump 文件，用 MAT 或 VisualVM 分析大对象、对象数量和引用链，判断是内存泄漏还是内存配置不足。最后根据原因修复代码，例如释放集合缓存、关闭资源、减少线程数，或者合理调整 JVM 参数。
