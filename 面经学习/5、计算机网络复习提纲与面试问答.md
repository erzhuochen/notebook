# 一、体系复习提纲

## 1. 学习目标

能从“一次浏览器请求到 Java 后端服务响应”出发，讲清 DNS、TCP、TLS、HTTP、认证状态、安全攻击和接口排查。

## 2. 核心主线

```text
输入 URL
-> 浏览器解析 URL
-> DNS 解析域名得到 IP
-> 建立 TCP 连接
-> HTTPS 场景进行 TLS 握手
-> 发送 HTTP 请求
-> 服务端处理请求
-> 返回 HTTP 响应
-> 浏览器接收并解析响应
```

## 3. 必会知识点

### DNS

- DNS 用于把域名解析成 IP。
- 常见解析链路：浏览器缓存、系统缓存、本地 DNS、根域名服务器、顶级域名服务器、权威域名服务器。
- DNS 结果会受缓存、TTL、CDN、负载均衡影响。

### TCP

- TCP 是面向连接、可靠、有序、基于字节流的传输层协议。
- 三次握手用于确认双方收发能力并同步初始序列号。
- 四次挥手用于双方分别关闭发送方向。
- 可靠性依赖序列号、确认应答、超时重传、滑动窗口、拥塞控制。

### HTTP

- HTTP 是应用层协议，核心是请求和响应。
- HTTP/1.1 支持长连接，但同一连接上仍可能出现队头阻塞。
- HTTP/2 使用二进制分帧、多路复用、头部压缩。
- HTTP/3 基于 QUIC/UDP，减少 TCP 层队头阻塞，支持更快建连和连接迁移。

### HTTPS / TLS

- HTTPS = HTTP + TLS。
- TLS 解决身份认证、加密传输、完整性校验。
- 证书用于证明服务端身份。
- 握手阶段协商会话密钥，业务数据通常使用对称加密传输。

### Cookie / Session / Token

- Cookie 是客户端存储机制。
- Session 是服务端会话状态，客户端通常只保存 SessionId。
- Token/JWT 通常由服务端签发，客户端携带，服务端校验签名、有效期和权限信息。
- 后端回答要围绕存储位置、是否有状态、扩展性、安全风险展开。

### Web 安全

- XSS：恶意脚本被注入并在用户浏览器执行。
- CSRF：利用用户已登录状态诱导浏览器向目标站点发送请求。
- DDoS：通过大量请求耗尽服务资源。
- SYN Flood：大量伪造 SYN 占满半连接队列。

## 4. 易错点

- HTTPS 不是全程都用非对称加密传输业务数据。
- HTTP/2 解决了 HTTP 层队头阻塞，但 TCP 丢包仍可能影响同一连接上的所有流。
- Cookie、Session、Token 不是同一层概念，Cookie 是载体，Session/Token 是认证方案的一部分。
- CSRF 不要求攻击者读取响应，只要能诱导浏览器发出带身份信息的请求就可能造成影响。
