## 二、高频面试题

### 1. TCP 为什么需要三次握手？

回答：

TCP 三次握手主要是为了确认客户端和服务端双方的**发送能力**和**接收能力**都正常，同时同步双方的**初始序列号 ISN**，并避免历史连接请求导致服务端建立错误连接。

第一次握手，客户端发送 SYN，服务端可以确认客户端具备发送能力，服务端具备接收能力。第二次握手，服务端返回 SYN + ACK，客户端可以确认自己发送、接收正常，也能确认服务端发送、接收正常。第三次握手，客户端返回 ACK，服务端才能确认客户端具备接收能力。三次完成后，双方都确认了彼此的收发能力，并同步了后续可靠传输需要的初始序列号。

如果只有两次握手，服务端发出 SYN + ACK 后就可能认为连接已经建立，但客户端可能没有收到响应，或者这只是一个历史 SYN 报文触发的连接请求，容易造成服务端资源浪费。SYN Flood 就是利用这个过程，大量发送 SYN 报文但不完成第三次握手，占满服务端半连接队列。常见防御方式包括 **SYN Cookie**、调大半连接队列、缩短超时时间、高防 IP 或流量清洗。SYN Cookie 不是 HTTP Cookie，而是服务端把连接必要信息编码进 SYN + ACK 的初始序列号中，等客户端第三次握手返回 ACK 后再校验并创建连接。

普通 TCP 下，第三次握手的 ACK 可以携带数据；第一次 SYN 通常不携带应用数据，但 **TCP Fast Open** 是特殊情况。
