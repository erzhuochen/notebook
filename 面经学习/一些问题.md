
# 一、Java基础
## jvm中多态本质

```java
public class Person{  
    public void methodA(){}  
    public void methodB(){}  
}  
class Boy extends Person{  
    public void methodA(){}  
}  
class Party{  
    public void party(){  
        Person bp = new Boy();  
        bp.methodA();  
    }  
}
```

字节码分析
```bash
 0 new #2 <Boy>                              # 在堆中为Boy对象分配空间，并把对象引用压入栈中      操作数栈:[boy_ref（所指向对象未初始化）]
 3 dup                                       # 把栈顶元素复制一份再压入栈中（栈中有两个Boy引用了） 操作数栈:[boy_ref（未初始化）、boy_ref（未初始化）]
 4 invokespecial #3 <Boy.<init> : ()V>       # 弹出操作数栈顶的元素，并调用它的 `<init>` 方法。   操作数栈:[boy_ref（已初始化）]
 7 astore_1                                  # 将操作数栈顶弹出，并存进局部变量表索引为1的位置     操作数栈:[]
 8 aload_1                                   # 将局部变量表索引为1的变量加载出来并压入栈          操作数栈:[boy_ref（已初始化）]
 9 invokevirtual #4 <Person.methodA : ()V>   # 将栈中元素弹出并调用person的methodA方法
12 return
```
这段字节码是如何体现多态的？

这段字节码中最关键的就是第 9 行的 `invokevirtual` 指令。

1. **静态类型（编译期）：** 在编译阶段，编译器只知道局部变量表 1 号位置的变量声明类型是 `Person`（因为你写的是 `Person p = ...`）。所以，在生成字节码时，第 9 行生成的常量池引用是 `#4 <Person.methodA : ()V>`。这也就是所谓的“编译看左边”。
    
2. **实际类型（运行期）与动态分派：** 当 JVM 运行到 `invokevirtual` 时，它**不会**盲目地去调用 `Person` 类的 `methodA`。相反，它的执行逻辑是这样的：
    
    - 首先，它会去操作数栈顶拿到那个引用（在这个例子中，引用实际上指向堆内存中的 `Boy` 对象）。
        
    - JVM 根据这个对象的**实际类型**（`Boy`）去查找方法。
        
    - 如果 `Boy` 类重写（Override）了 `methodA`，JVM 就会调用 `Boy` 类的 `methodA`。
        
    - 如果 `Boy` 类没有重写，JVM 才会沿着继承链向上，去调用父类 `Person` 的 `methodA`。
