#### TLS
RSA：
```mermaid
sequenceDiagram
    客户端 ->> 服务器: 生成随机数a并发送
    服务器 ->> 客户端: 接收并生成随机数b。发送b和公钥
    客户端 ->> 服务器: 接收并生成随机数c，用公钥加密c后发送
    服务器 ->> 客户端: 使用私钥解密获得c
    服务器 -->> 客户端: 此时双方都有a,b,c。使用a,b,c实现对称加密通信
```

ECDHE:
- ClientRandom和ServerRandom不用其实也不会被重放攻击，加上是为了增加混乱度

```mermaid
sequenceDiagram
    participant Client as 客户端
    participant Server as 服务器
    
    Client->>Server: 1. 生成常规随机数 ClientRandom<br/>2. 生成曲线私钥a，算出公钥份额 A(=G*a)<br/>3. 发送 ClientRandom + A
    
    Server->>Client: 1. 生成常规随机数 ServerRandom<br/>2. 生成曲线私钥b，算出公钥份额 B(=G*b)<br/>3. 掏出私钥，对(A+B)做数字签名<br/>4. 发送 ServerRandom + B + 证书 + 数字签名
    
    Note over Client: 1. 用证书公钥验证数字签名(防伪)<br/>2. 算出共享密钥 Secret = (A*b) = (B*a)
    
    Note over Client,Server: 双方底层独立推导：最终对称密钥 = ClientRandom + ServerRandom + Secret
    
    Client<<->>Server: 使用最终对称密钥进行强加密通信
```

#### HTTP3.0
与2.0区别：
1. **传输层协议**：
   - 2.0 tcp  
   - 3.0 udp
2. **彻底解决队头阻塞**：
   - 2.0 Stream A 的包丢了，TCP会暂停所有流的传输，等待重传；
   - 3.0 Stream A的包丢了，应用层会阻塞Stream A，其他Stream不影响
3. **建连速度**：
   - 2.0：TCP三次握手（1RTT）+TLS握手（1/2 RTT）
   - 3.0：QUIC把传输层握手加密握手合并了（1RTT）。如果之前连过，且执行幂等操作，可以直接0RTT发送数据。
4. **连接迁移**：
   - 2.0：基于四元组识别。当你从wifi切到4G，IP变了，连接就断了，必须重连。
   - 3.0：基于**Connection ID**。
1. **头部压缩算法升级**：
   - 2.0：使用HPACK，依赖TCP的顺序接收。
   - 3.0：使用QPACK。使用专门的流来传输动态表更新指令。发送数据时若使用了接收端未确认的索引，可以选择直接发送字面量。
