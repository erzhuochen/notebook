#### 用户态和内核态

内核态：权限 Ring 0。位于虚拟地址空间的高地址区，
       所有进程共享同一份内核映射，可执行特权指令。

用户态：权限 Ring 3。位于虚拟地址空间的低地址区，
       每个进程有独立的用户空间，进程切换需要切换页表和上下文。

read() 系统调用过程：
1. 用户态调用 read()，执行 syscall 指令触发 trap
2. CPU 切换到 Ring 0，进入内核态（涉及栈切换、可能污染 CPU 缓存/TLB）
3. 内核查 Page Cache：
   - 命中 → 直接拷贝到用户缓冲区
   - 未命中 → 发起磁盘 DMA 读取，当前进程睡眠等待
4. 数据到达后，从内核缓冲区拷贝到用户空间
5. 切换回 Ring 3 用户态，返回结果

上下文切换辨析：
- 系统调用：只做模式切换（用户态→内核态），不切换进程，
  仍在当前进程上下文中执行，开销较小
- 异常（如缺页）：同上，也在当前进程上下文中处理
- 硬件中断：进入中断上下文，不属于任何进程，不能睡眠
- 进程切换：需要切换页表、寄存器、栈等完整上下文，开销最大

#### 线程和进程

  

|             | 线程                                                                  | 进程                                   |
| ----------- | ------------------------------------------------------------------- | ------------------------------------ |
| **定义**      | 进程中的一个执行单元，是 CPU 调度的基本单位                                            | 资源分配的基本单位，有独立的地址空间                   |
| **空间**      | 共享：堆、代码段、全局变量、文件描述符、页表  <br>独立：**栈**、**寄存器**、**PC**、**ThreadLocal** | 地址空间完全独立，互不可见                        |
| **切换开销**    | 小：不切换页表，不刷 TLB，CPU 缓存更可能命中                                          | 大：切换页表 + 刷新 TLB + CPU 缓存大概率失效        |
| **通信**      | 直接读写共享内存，速度快  <br>但需要同步机制（锁、CAS）防止竞态                                | 需要 IPC 机制：管道、消息队列、共享内存、信号、信号量、Socket |
| **安全性/隔离性** | 差：一个线程崩溃可能导致整个进程崩溃                                                  | 好：一个进程崩溃不影响其他进程                      |
| **创建开销**    | 小：只需分配栈和少量管理结构                                                      | 大：需要分配独立地址空间、拷贝页表等                   |

java：

|概念|Java 体现|
|---|---|
|线程共享堆|Java 对象都在堆上，多线程可直接访问，所以才需要 `synchronized`、`volatile`|
|线程栈独立|局部变量天然线程安全（存在各自的栈帧中）|
|ThreadLocal|对应线程独立的 TLS（线程本地存储）|
|线程崩溃拖垮进程|Java 中一个线程抛出未捕获异常，默认只杀该线程；但如果是 OOM 等问题，可能影响整个 JVM 进程|
|进程隔离好|微服务架构：每个服务是独立进程，一个服务挂了不拖垮其他服务|

#### 进程通信方式
- 管道：接收方被动接收
- 消息队列：接收方主动从队列中取出需要的消息
- 共享内存：一块双方都能读写的内存，通信方式自由，想怎么读写都可以
- 信号：例如IO会产生信号告诉CPU去读取
- 信号量：本质就是一个用来计数的数，例如分配锁时设置信号量为3，线程使用一个锁，信号量减一，信号量为0时，请求锁的线程需自旋等待或睡眠等待信号（上面提到的那个信号）提醒。
- socket：一种逻辑概念，抽象出通信的接口，两个socket之间能建连

| 方式         | 原理                               | 特点                                         | 适用场景                   |
| ---------- | -------------------------------- | ------------------------------------------ | ---------------------- |
| **管道**     | 内核中的环形缓冲区，半双工，数据先进先出             | 简单；匿名管道仅限父子进程；数据读走即消失                      | 简单的父子进程通信，如 shell 管道   |
| **消息队列**   | 内核中的链表，按消息类型存取                   | 可按类型选择性接收；有格式；生命周期独立于进程                    | 需要结构化数据、解耦的通信          |
| **共享内存**   | 多个进程映射同一块物理内存                    | **最快**（零拷贝）；但必须自行解决同步问题                    | 大数据量、高频率通信             |
| **信号**     | 发给进程的异步通知（编号）。<br>区分：IO时发送的是硬件中断 | 只能传一个信号编号，不传数据；异步                          | 通知进程某事件发生（kill、Ctrl+C） |
| **信号量**    | 受保护的计数器 + P/V 操作                 | 本质是**同步机制**，不传数据                           | 控制并发数量、互斥访问            |
| **Socket** | 抽象的通信端点（IP+端口 或 文件路径）            | **唯一可跨机器**的 IPC；也可本机通信（Unix Domain Socket） | 网络通信、跨机器进程间通信          |

**与 Java 后端关联**

|IPC 方式|Java / 中间件映射|
|---|---|
|管道|`ProcessBuilder` 启动子进程时的输入输出流|
|消息队列|Kafka、RocketMQ、RabbitMQ（应用层消息队列）|
|共享内存|`MappedByteBuffer`（mmap 内存映射文件），Netty 的堆外内存|
|信号|`kill -15` 优雅停机 → Spring Boot 的 Shutdown Hook|
|信号量|`java.util.concurrent.Semaphore`|
|Socket|最常用——HTTP、RPC（Dubbo）、数据库连接，全是 Socket|
