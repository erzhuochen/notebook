# 三、项目亮点模板

## 缓存亮点

```text
问题：
某个接口访问频率高，如果每次都查数据库，压力较大。

方案：
使用 Redis 缓存热点数据，请求先查缓存，缓存未命中再查数据库并回写缓存。

需要考虑：
缓存穿透、缓存击穿、缓存雪崩、缓存一致性。

面试回答：
我不是简单地加缓存，而是考虑了 key 设计、过期时间、异常兜底和一致性问题。
```

## 事务亮点

```text
问题：
一个业务操作需要同时更新多张表，如果中间失败，数据可能不一致。

方案：
使用 Spring 声明式事务保证原子性。

需要考虑：
事务传播行为、异常回滚规则、同类调用导致事务失效。

面试回答：
我会特别注意事务方法必须通过 Spring 代理调用，并且异常不能被吞掉。
```

## 并发亮点

```text
问题：
多个请求同时修改同一资源，可能出现超卖、重复提交、状态覆盖等问题。

方案：
根据场景选择数据库唯一约束、乐观锁、悲观锁、Redis 分布式锁或消息队列削峰。

需要考虑：
锁粒度、锁超时时间、异常释放、幂等性。
```

## 性能优化亮点

```text
问题：
接口响应慢。

排查顺序：
请求链路耗时 -> SQL 慢查询 -> Redis 命中率 -> 线程池状态 -> GC 日志 -> 外部接口耗时。

优化方式：
加索引、减少 N+1 查询、缓存热点数据、异步化非核心逻辑、批量处理。
```

# 五、模拟面试流程

## 第一轮：项目介绍

1. 30 秒介绍项目。
2. 说明你负责的模块。
3. 讲一个项目难点。
4. 讲一个优化点。

## 第二轮：技术追问

按项目中出现的技术逐个追问：

```text
为什么用这个技术？
不用它会有什么问题？
底层原理是什么？
有没有踩过坑？
如果数据量/并发量扩大 10 倍怎么办？
```

## 第三轮：综合场景题

常见场景：

- 接口突然变慢，怎么排查？
- Redis 缓存击穿，怎么处理？
- MySQL 慢 SQL，怎么优化？
- 线程池打满，怎么排查？
- 服务 OOM，怎么定位？
- Spring 事务没有回滚，可能是什么原因？
