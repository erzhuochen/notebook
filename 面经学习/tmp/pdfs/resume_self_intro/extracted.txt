直播平台
一款企业级直播平台后端服务，涵盖直播间管理、礼物互动、红包雨、连麦PK、弹幕推送等核心业务场景，解决直播场景下高并
发抢红包、送礼扣款一致性、实时消息推送等核心痛点，适配电商、娱乐类直播业务需求。
技术栈: Spring Boot 、Spring MVC、Spring Cloud Gateway、Dubbo、Nacos、Kafka、Redis、MySQL、MyBatis-Plus、
ShardingSphere-JDBC、Caffeine、Netty WebSocket
项目介绍:
①功能点 :
· 网关登录认证：基于Nacos动态白名单放行匿名接口；从Cookie提取token，经Dubbo调用账号服务查询userId，并通过内部
请求头传递给下游服务，对无效登录态请求进行拦截。
· 直播间生命周期管理：开播时创建有效直播间记录、清理对应房间对象缓存，并通过Kafka异步查询主播关联SKU，将库存预
热至Redis；关播时校验主播身份，使用MySQL本地事务完成直播记录归档和当前房间记录删除，并清理Redis缓存。
· 直播列表缓存：针对直播列表读多写少场景，使用Redis List支持分页读取；通过定时任务从MySQL刷新直播数据，先写临时
List，再使用Redis RENAME原子替换正式缓存，避免请求读到刷新过程中的半成品列表。
· 礼物互动：API侧使用Caffeine缓存礼物配置，以服务端配置确定礼物价格并投递Kafka；消费者使用消息UUID与Redis SET
NX进行5分钟有限时间去重，降低同一消息短时间重复投递造成重复扣款的风险，扣款成功后推送礼物特效。
· 红包雨：采用二倍均值法拆分红包金额并分批写入Redis List，领取时使用rightPop原子分配金额；领取后返回成功并投递
Kafka，由消费者异步更新领取统计并调用账户服务入账，缩短抢红包接口的同步处理链路。
· 直播PK：使用Redis SET NX实现房间维度的PK参与位互斥占用；基于Redis Lua原子初始化并更新PK进度，避免并发送礼导
致更新丢失，并向直播间在线用户批量推送进度和礼物特效。
· 实时消息推送：基于Netty WebSocket维护长连接，通过Kafka传递用户上线、下线和业务消息；使用Redis Set维护直播间在
线成员，Router批量查询用户绑定的实例地址并按实例分组调用Dubbo RPC，将跨服务调用量由按用户调用降低为按IM实例
调用。
